PASS (with one precision note on “LIBOQS_LIBS unchanged”)

Why Option A was misreported before

1. With depends, liboqs.a lives under the depends host prefix, e.g.  
   depends/x86_64-linux-gnu/lib/liboqs.a (present on this machine).
2. Old code used $prefix → if unset/NONE, ac_default_prefix → typically /usr/local/lib/liboqs.a, which is not where depends installs.
3. File test failed → liboqs_found=no → Option B notice via PKG_CHECK_MODULES (configure.ac:1644–1648).
4. Under depends, that still often succeeds: config.site forces PKG_CONFIG_LIBDIR / PKG_CONFIG_PATH into the depends tree (depends/config.site.in:87–89) and PKG_CONFIG="… --static" (:82). Local liboqs.pc points at the same archive (prefix=…/depends/x86_64-linux-gnu, Libs: -L${libdir} -loqs).

So you get the label “Option B” while still linking the pinned depends static library — matches the reported mis-detection.

Why the fix yields Option A

• depends_prefix is non-empty under CONFIG_SITE → liboqs_prefix=${depends_prefix} (configure.ac:1628–1629).
• test -f "${liboqs_prefix}/lib/liboqs.a" succeeds → Option A notice and hard-coded flags.
• Confirmed in current config.log:  
  liboqs: Option A — static lib at /home/virtualbox/qogecoin/depends/x86_64-linux-gnu/lib/liboqs.a  
  and  
  LIBOQS_LIBS='-L/home/virtualbox/qogecoin/depends/x86_64-linux-gnu/lib -loqs -lcrypto'.

“Linked library unchanged”

Plausible and well-supported: both pre-fix Option B (depends pkg-config) and post-fix Option A resolve to the same depends/.../lib/liboqs.a. LDFLAGS also already includes -L${depends_prefix}/lib from config.site.in:93.

Precision note on “LIBOQS_LIBS is unchanged” as a string

If the pre-fix path was truly Option B, LIBOQS_LIBS came from pkg-config (Libs: -L… -loqs plus static expansion of Requires.private: openssl), not from the Option A line -L… -loqs -lcrypto. Those strings can be equivalent for linking without being byte-identical. If the empirical claim is “same resolved archive / same effective link,” PASS. If it means the exact LIBOQS_LIBS= line in config.log never differed across a true B→A transition, that is slightly stronger than the code guarantees; I did not re-run pre-fix configure here to re-measure that string.
